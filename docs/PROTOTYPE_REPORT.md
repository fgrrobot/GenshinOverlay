# Отчёт о прототипе Teyvat Lens

**Версия:** 0.2 (MVP-прототип)
**Дата:** 2026-11-12
**Связанные документы:** `PROJECT.md` (полная спецификация), `docs/ARCHITECTURE.md`, `docs/PLAN.md`

---

## 1. Цель и границы прототипа

Цель — проверить жизнеспособность ключевой идеи проекта на минимальном объёме кода:
**можно ли определять положение игрока по изображению миникарты достаточно точно, чтобы
показывать ближайшие объекты, и укладывается ли это в бюджет времени кадра.**

В прототип сознательно не входят:

- абсолютная релокализация по атласу (ORB/RANSAC) и фильтр Калмана;
- прозрачное click-through окно поверх игры и Windows Graphics Capture;
- реальный пакет данных сообщества и тайлы карты;
- горячие клавиши, трей, DPI/HDR-обработка.

Вместо этого прототип проверяет то, что легче всего проверить неправильно: геометрию,
одометрию, хранение прогресса и связку «локализация → запрос к базе → подсказка → интерфейс».

## 3. Хранение данных

SQLite в режиме WAL. Схема:

| Таблица | Содержимое |
|---|---|
| `marker_kind` | код, русское название, цвет, приоритет, глиф |
| `marker` | координаты X/Z, высота Y, слой, регион, источник |
| `marker_rtree` | R\*Tree-индекс для запроса «объекты в радиусе» |
| `marker_state` | отметки `collected` / `ignored`, время сбора |
| `setting` | радиус, фильтр типа, режим, область захвата, масштаб |

Демонстрационное наполнение — 142 синтетических маркера: 114 базовых объектов
(сундуки, руда, цветы, грибы, рыба, кристаллы), скопления ресурсов и 4 точки телепорта.
Наполнение детерминированное (фиксированный seed), повторный `SeedIfEmpty` ничего не дублирует.

Прогресс и настройки сохраняются между запусками; `ResetProgress` очищает только `marker_state`.

## 4. Локализация

### 4.1 Конвейер

1. Кадр миникарты приводится к серому и обрезается круглой маской (размер сохраняется).
2. `OdometryTracker` применяет CLAHE, переводит кадр в `float32 0..1`.
3. Соседние кадры умножаются на окно Ханна и сравниваются фазовой корреляцией.
4. Пик корреляции уточняется параболической подгонкой по трём точкам.
5. Сдвиг контента пересчитывается в мировые метры через `px_per_meter`.

### 4.2 Почему своя фазовая корреляция

Встроенный `Cv2.PhaseCorrelate` систематически занижает дробную часть сдвига: при истинном
смещении 0.5 px он возвращает ≈0.175 px. На длинной дистанции это превращается в ошибку
масштаба в единицы процентов. Параболическая подгонка по трём точкам даёт точность порядка
сотых долей пикселя.

Второй источник ошибки — предварительный ресайз 360 → 256 px. Он заметно искажает
субпиксельную оценку, поэтому корреляция выполняется **на нативном разрешении** миникарты,
а масштаб берётся из исходного кропа.

### 4.3 Автомат состояний

| Состояние | Условие | Поведение |
|---|---|---|
| `Tracking` | уверенность > 0.7 | позиция и объекты показываются |
| `Degraded` | 0.4 < уверенность ≤ 0.7 | позиция показывается с предупреждением |
| `Lost` | сигнал пропал дольше 1.5 с или скачок > 120 м | позиция скрывается, требуется привязка |

Уверенность — экспоненциально сглаженная высота пика корреляции. При `Lost` приложение
не «доползает» по старой позиции, а честно просит привязаться к телепорту.

## 5. Интерфейс

Тёмная тема WPF, окно 1280×820:

- карта вокруг игрока с атласом, кольцами радиуса, маркерами и стрелкой игрока;
- компас с направлением взгляда и азимутом цели;
- нижняя подсказка: имя цели, расстояние, относительное направление, «выше/ниже»;
- список ближайших объектов с расстоянием и направлением, обновляется на месте без мигания;
- панель привязки к телепорту, фильтр типа, радиус поиска, сброс прогресса;
- переключатель «Потерять сигнал миникарты» для демонстрации `Lost`.

Скриншот: `docs/screenshot.png`.

на стороне анализа. Основное ограничение — не скорость, а накопление дрейфа.

## 7. Известные ограничения

1. **Дрейф.** Относительная одометрия накапливает ошибку ≈ 4 % пути. После длинного перехода
   нужна повторная привязка к телепорту. Лечится абсолютной релокализацией и фильтром Калмана.
2. **North-up.** Миникарта считается ориентированной на север. Если игра вращает её вместе
   с камерой, корреляция увидит поворот как плохое совпадение и уйдёт в `Lost`.
3. **Захват GDI.** `BitBlt` не работает с аппаратно-ускоренными и эксклюзивными окнами;
   требуется borderless-режим. Целевое решение — Windows Graphics Capture.
4. **Нет настоящего оверлея.** Окно обычное, не прозрачное и не click-through; оно не
   исключается из захвата. Это следующий крупный шаг.
5. **Нет абсолютной локализации.** Атлас используется только для отрисовки, не для поиска позиции.
6. **Один слой.** Подземелья и многослойные регионы не поддерживаются.
7. **Нет таймеров возрождения** ресурсов, горячих клавиш, трея и установщика.
8. **Режим захвата не проверен на живой игре** — в среде разработки игра недоступна;
   проверены демо-мир и модульные тесты.
9. **Данные синтетические.** 142 маркера — тестовый полигон, а не выгрузка из игры.

## 8. Планы развития

1. **Абсолютная релокализация:** ORB/AKAZE + RANSAC по атласу, ограничение поиска кругом
   вокруг текущей оценки, fallback на нормированную кросс-корреляцию.
2. **Слияние:** фильтр Калмана `[X, Z, VX, VZ]`, одометрия как управляющий вход, отбраковка
   измерений по расстоянию Махаланобиса, сброс фильтра при телепорте.
3. **Захват:** Windows Graphics Capture + D3D11-текстура, исключение оверлея через
   `WDA_EXCLUDEFROMCAPTURE`.
4. **Оверлей:** DirectComposition, премультиплицированная альфа, click-through, горячая клавиша.
5. **Данные:** импорт версионированного пакета маркеров и тайлов, R\*Tree на полном объёме,
   таймеры возрождения ресурсов.
6. **Калибровка:** автопоиск круга `HoughCircles`, профили под разрешение и HUD-scale, DPI v2.
7. **Качество:** регрессия на записанных сессиях, метрики медианы/p95 ошибки в CI.
